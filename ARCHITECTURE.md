## High-Level Components

- **Health Helper**
  - Сервис для поддержки здоровья системы: проверки состояния, метрики, автоматический рестарт / backoff.
  - Не содержит бизнес-логики, только инфраструктуру (наблюдаемость, алерты).

- **Контроллеры рынков (Market Controllers)**
  - Отвечают за конкретный класс активов: криптовалюта, акции, форекс, металлы, сырьё.
  - Знают, какие индикаторы, таймфреймы и особенности ликвидности/волатильности нужны для своего рынка.
  - Нормализуют сырые данные в единый формат для ядра и AI.

- **Контроллеры брокеров (Broker Controllers)**
  - Инкапсулируют работу с конкретным брокером / биржей (Bybit и др.).
  - Предоставляют унифицированный интерфейс: ордера, балансы, позиции, лимиты, спецификации контрактов.
  - Содержат защиту от специфических ошибок API и rate limit-ов.

- **Сборщик контекста (Context Aggregator)**
  - Собирает новости, индикаторы, движения цены, внешние сигналы.
  - Строит «контекстную записку» для AI: universe, метаданные, резюме рынка, risk-состояние.
  - Контролирует объём контекста и лимиты токенов.

- **Контроллеры AI-вендоров (AI Provider Controllers)**
  - Абстрагируют OpenAI / DeepSeek и другие модели.
  - Управляют выбором модели, бюджетом токенов, стратегией ретраев, логированием запросов.
  - Предоставляют две главные операции: построение universe и построение trade plan.

- **Юзерботы (UserBot Workers)**
  - Воркер на пользователя: читает trade plan и применяет его к счёту.
  - Хранит user-specific state: ключи, Telegram, логи, риск-параметры, отдельный runtime.
  - Не занимается AI и построением universe — только исполнением и мониторингом.

- **Ядро / Движок (Engine Core)**
  - Центральный сервис, который соединяет рынки, брокеров, контекст и AI.
  - На вход получает universe / состояние рынка, на выход даёт trade plan.
  - Работает без пользовательских ключей, используя только публичные данные и AI.


## Roadmap (Этапы развития)

1. **Стабилизация текущего монолита**
   - Убедиться, что `bybitbot_impl.run_cycle` работает как раньше (регрессия по логам/ордерам).
   - Execution/protection/trailing logic is now in `order_executor.py` and `protection_engine.py`; impl keeps thin wrappers.
   - Зафиксировать формат runtime-снапшотов (`runtime/engine/trade_plan.json`).

2. **Выделение ядра и userbot-воркера**
   - Уточнить интерфейс `build_trade_plan_snapshot` и `apply_trade_plan_snapshot` как контракт ядро ↔ юзербот.
   - Привести `bybit_engine.py` и `bybit_userbot.py` к использованию этих контрактов без дублирования логики.

3. **Скелет сервисов**
   - Ввести базовые классы из `architecture_skeleton.py` для:
     - HealthHelper
     - MarketController
     - BrokerController
     - ContextAggregator
     - AIProviderController
     - UserBotWorker
     - EngineCore
   - Подготовить конфигурацию, которая позволит в будущем подменять реализации.

4. **Первый рынок и брокер**
   - Реализовать минимальный `MarketController` для криптовалют (Bybit).
   - Обернуть текущий `ccxt.bybit` в `BrokerController` для единообразного интерфейса ордеров и позиций.

5. **Контекст и AI-провайдер**
   - Вынести сбор новостей/индикаторов/контекста в `ContextAggregator`.
   - Завернуть вызовы OpenAI в `AIProviderController` с контролем токенов и retry-политикой.

6. **Интеграция с EngineCore**
   - Подключить `MarketController`, `BrokerController`, `ContextAggregator` и `AIProviderController` к `EngineCore`.
   - Перенести текущую реализацию `build_trade_plan_snapshot` внутрь `EngineCore`, сохранив старый интерфейс.

7. **Расширение рынков и брокеров**
   - Добавить дополнительные `MarketController` (акции, форекс, металлы) по мере необходимости.
   - Добавить новые `BrokerController` (другие биржи / брокеры) с минимально совместимым API.

8. **Оркестрация и наблюдаемость**
   - Подключить `HealthHelper` для всех сервисов: health-check-и, метрики, алерты.
   - Определить, как `bybitbot.py` будет работать как оркестратор (запуск EngineCore + userbot workers).

9. **Постепенная миграция**
   - Запускать новую модульную архитектуру параллельно со старым `run_cycle`, сравнивая trade plans и исполнение.
   - После достаточной валидации постепенно отключать монолитные части, оставляя только модульные сервисы.
